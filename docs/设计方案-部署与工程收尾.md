## 3. 设计决定

**D1 compose 只描述「核心必起 + 可选壳」两服务，口径逐字段对齐 §8。**
`seekdb`：`image: quay.io/oceanbase/seekdb:latest`、`container_name: seekdb`、
`ports: "2881:2881"`、`volumes: seekdb_data:/var/lib/seekdb`、
`environment: MEMORY_LIMIT=2G / REPORTER=docker-seekdb`、`restart: unless-stopped`、
`healthcheck` 用容器内 `mysqladmin ping`（没有客户端就退回 `curl -sf http://127.0.0.1:2881`? 见 §8 实测：
健康判定改用 `docker exec` 侧的 TCP 探活，避免镜像里没装 `mysql` 时误判 not-ready）。
`web`：`profiles: ["web"]`、两阶段构建（`node:22-alpine` 构建 dist → `nginx:alpine` 托管）。
**named volume 沿用既有 `seekdb_data`**（compose 里声明 `external: true`，
这样 `docker compose down` 绝不会把 2.2G 数据卷删掉——这是本卡最硬的一条安全边界）。

**D2 web 容器只做两件事：托管 dist + 反代 `/api`。**
nginx `location /api/ { proxy_pass http://host.docker.internal:8000; }`，
SSE 必须 `proxy_buffering off` + `proxy_read_timeout 1h` + `chunked` 友好（`X-Accel-Buffering: no`
由后端 SSE 响应头带上，nginx 侧关缓冲即可）；SPA 走 `try_files $uri /index.html`。
后端不进 compose（venv 在宿主机，演示口径与 §9.8「零浏览器也要能跑」一致）。
`extra_hosts: host.docker.internal:host-gateway` 保证 Linux 引擎上也能解析到宿主机。

**D3 key 合规：镜像里不 bake 任何 key。**
`web/.dockerignore` 排除 `.env`，构建参数 `VITE_AMAP_KEY=${VITE_AMAP_KEY:-}` 由宿主环境注入；
不注入就构建出**降级档**（SVG 底图），两档本来都是交付面。compose 里 `build.args` 只引用变量名，
不写值，`.env` 也不入库。

**D4 换容器的动作要可回退。**
`docker compose up -d` 与现役 `docker run` 容器同名会冲突，但**不删旧容器**：
先 `docker stop seekdb` → `docker rename seekdb seekdb_precompose`（旧容器连同一份 volume 一起留着），
再 compose 起新容器；验收数据基线（§1 的五个行数）逐条对上才算通过。
要回退就 `docker compose stop seekdb && docker rename seekdb_precompose seekdb && docker start seekdb`。
旧容器最终是否 `docker rm` 由用户拍板——**我不主动删**。

**D5 拆分硬闸：测试除 import 行外零改动。**
`constraints.py` 拿 `_constraints_node` 的函数体（spec 装配 + `ConstraintOverrides` 三路交集 +
`emit(constraints.updated)`），`synthesize.py` 拿 `_decide_node` 的函数体（决策特征拼装 +
LLM 调用 + 降级模板）。graph.py 保留：`BrainState`、`_CHECKPOINTER`、节点包装（`intent` 的
`interrupt` 编排、`candidates/spatial_join/render/feedback` 因为与 `ctx.tools`/`build_graph` 闭包
强相关，本卡**不搬**）、`build_graph`、`run_query/resume_query`、`state_to_spatial_state`，
并继续 re-export `GRAPH_NODES / run_query / resume_query / build_graph / _constraints_node /
_iso_request / _iso_matches / _isochrone_update / state_to_spatial_state / SkillRegistry`——
现有 6 个 import 站点（routes / demo / 4 个测试文件）一字不改。
`state_manager.py` 不建：「依赖图 / stale 标记 / 局部重算」这三件事现在真的住在
`backend/state/repository.py`（`mark_stale` / `replan`）里，再包一层空壳等于制造第二处真相。
搬移过程只允许「剪切函数体 → 新模块同名函数 → 原位置调用」，任何断言/用例需要改逻辑就停下汇报。

**D6 §9.8 终验脚本按原文五步，且必须能自己判红。**
`docs/sql/verify_removable.sh` 用 `set -euo pipefail` + `curl -sf` + `python -c` 解 JSON 断言：
①建会话（断言 `session_id` 非空）②后台订阅 SSE 到临时文件 ③发查询（断言候选数 > 0 且
`map_spec.layers` 含 poi 图层）④拉 `l_candidates` GeoJSON（断言 `type=FeatureCollection` 且
`features` 非空）⑤`feedback` 一条 `constraint_edit`（断言 `accepted=true`）⑥最后从 SSE 文件里
断言至少出现过 `layer.update` 与 `message.end` 两类事件。全程 `--no-web`：脚本只打 8000 端口。
退出码非 0 即为失败，并把每步实际值打到 stdout（不给「看起来过了」留空间）。

## 7. 风险

| 项 | 处置 |
|---|---|
| compose `down` 误删 2.2G 数据卷 | `seekdb_data` 声明 `external: true`（compose 不拥有它）；已实证：`down` 后 `docker volume inspect` 创建时间仍 `2026-10-15T02:39:53Z`，重新 `up` 后 `dim_poi` 20000 行 |
| 换容器时旧容器被删导致回退无路 | D4：只 `stop + rename`（旧容器留作 `seekdb_precompose`），`docker rm` 留给用户 |
| 基础镜像 `docker.io` 本机直连不通 | 与 §8 当年选 `quay.io` 同一原因（实测 `registry-1.docker.io` / `auth.docker.io` 6–8 s 超时 000）。`web/Dockerfile` 的 `FROM` 保持官方名，**不擅自改成第三方镜像站前缀**——换源是供应链决定，等用户拍板；`profiles` 默认不起 web 的语义不受影响 |
| Docker 里 npm 拉不到包（代理时有时无） | `.npmrc` 走 npmmirror 已在仓库里；容器构建依赖宿主网络属部署面事实，不影响 `profiles` 默认不起 web 的验收 |
| nginx 缓冲把 SSE 憋成「没事件」 | `proxy_buffering off` + `proxy_read_timeout 3600s`；反代通不通按容器路径实跑一次 chat 再从 SSE 文件断言事件 |
| 纯搬移把 emit 顺序/参数改歪 | 硬闸是「测试除 import 行外零改动」+ 变异检查 4/4（把搬出的节点改回本地空装、把覆盖判据空转、去掉兜底分支都必红）；不行就整块 `git checkout` 回退 |
