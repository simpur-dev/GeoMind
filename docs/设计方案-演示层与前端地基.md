## 3. 五个关键设计决定

### D1：坐标系转换放后端，前端零计算

- 库内 WGS84（DDL 铁律，SRID 0 存值）→ 高德底图 GCJ-02，不转换会有 300–600 m 偏移。
- **后端 `api/geo.py` 提供 `wgs84_to_gcj02(lon, lat)`**（标准非线性变换，公开算法），GeoJSON 端点在产出时即转换；前端只渲染。
- 依据 §9.6 职责边界表"空间计算 → 后端"；也符合"三不原则"第 3 条（前端不做计算裁决）。转换函数是**纯函数 + 可对拍**（round-trip 与已知基准点断言，见 §6）。
- 后端同时下发 `viewport.center`（GCJ-02）与 POI 的 `wgs84` 原值双写？**不**——只发 GCJ-02，契约干净；框选手势回传时前端回传 GCJ-02 坐标，后端在 L1 翻译层转回 WGS84 再进约束（翻译层新增 `gcj02_to_wgs84`，与 geo.py 同源）。

### D2：Map Spec 以架构 §9.3 的 kind 注册表为准，修订后端产出

- `site_selection.render_spec` 改产出：`kind="poi"`（非 points）、`source={"href": "/api/sessions/{sid}/layers/{id}", "type": "geojson"}`、`interactions`、`status`、`derived_from`；新增 `map_view`（center/zoom/pitch）与 `panels`（ranking/metrics）。
- 新增 `backend/api/contracts/map_spec.py`：`LayerSpec`/`MapSpec`/`PanelSpec` Pydantic 模型，**渲染器与后端共用同一份 schema**（后端 import 校验产出，前端 TS 接口手写对齐，靠测试钉死）。

### D3：渲染器 = kind 注册表 + 增量 diff

- `web/src/layers/`：`registry.ts`（kind → 渲染工厂）、`poi.ts`（MultiMarker + 打分标签）、`heatmap.ts`（Loca/高德 HeatMap）。
- 收到新 Map Spec：与上一份做 **layer id 级 diff**（新增/移除/更新三态），只动变化图层（§4.2 铁律）；`status == "stale"` 的图层先隐藏旧几何再拉新数据。
- 前端零业务判断：颜色/半径全部来自 `style` 字段，不含任何写死的业务常量。

### D4：SSE 事件总线（进程内，最小可用）

- `backend/api/sse_bus.py`：`EventBus`（dict[sid, list[asyncio.Queue]] + 环形缓冲存最近 N 条带 seq）。
- 断线续传：客户端带 `Last-Event-ID: <seq>` → 重放缓冲中 seq 之后的全部事件（§9.3 契约要求）。
- 图执行埋点：`backend/brain/graph.py` 的 7 节点在 `run_query` 外由 routes 层包裹发事件（tool.start/end、intent.updated、constraints.updated、layer.update、decision.updated、interrupt.required、state.delta、message.start/end/error）。
- 单进程部署下这是正解；多 worker 时换 Redis Pub/Sub 的接口已留出（EventBus 是抽象类，本环境不实现 Redis 版，仅注明）。

### D5：高德 key = 合规占位符 + 无 key 降级

- 地图数据合规白名单内选型：高德（架构 §9 既定）。
- key 合规硬规则：**不内置任何有效 key**。`web/.env.example` 与 `MapCanvas.vue` 均用显式占位符 `key="Please apply for your own key at the AMap Open Platform and replace this placeholder"`，并在 README 写申请入口（lbs.amap.com → 控制台 → 应用管理 → 创建应用 → Web 服务/Web 端 JS API key + Referer 白名单）。
- **无 key 降级模式**（保链路可演示）：检测 `VITE_AMAP_KEY` 未配置 → 不加载高德 SDK，渲染器切到内置的"坐标系画布"（SVG 投影 + 网格 + POI 点 + 热力方块，WGS84→GCJ-02 后的数据照常消费），顶部显示提示条"未配置高德 key，当前为无底图降级模式"。这样 #7 的 hello-world 与框选回传**不依赖 key 即可验收**，key 填上后自动升高德底图，渲染器代码路径不变（同一份 Map Spec）。

### 8.2 本轮实测修掉的 4 个坑（都是根因级）

1. **SSE 首字节被压住**：事件流在首个真实事件前不发任何字节 → EventSource 的 open 事件迟迟不触发，前端一直显示"未连接"。修法：流建立时立即发 `retry + ": connected"` 注释行，空闲期每 15 s 心跳注释（防代理掐静默长连接）。
2. **Decimal 打断 SSE 事件流**：`model_dump()` 不带 `mode="json"` 时 `avg_rating` 保留 Decimal，SSE 生成器 `json.dumps` 在 `decision.updated` 上抛 TypeError，**整条事件流从此断掉**（且无 HTTP 错误，极难察觉）。修法：图节点落状态统一 `model_dump(mode="json")`。
3. **降级渲染器 `<g>` 从未挂载**：fallback 渲染器把几何画进自建 `<g>`，但该节点没有 append 进 SVG——上一手被中断前没做过视觉验证。修法：构造函数挂到 `layersRoot`（公开）。
4. **spec 签名 diff 漏掉"数据变了、声明没变"**：框选重跑后候选集更新，但 layer id/kind/style 原样 → 增量 diff 判定"无变化"→ 旧几何残显。修法：diff 触发条件增加"数据引用变化"（`data !== appliedData.get(id)`），既守住 §4.2 只动变化图层的铁律，又保证数据变化必重绘。

### 8.3 高德 key 状态

用户已提供 Web端(JS API) key，写入本地 `web/.env`（被根 `.gitignore` 排除，**不入库**，符合架构 §9.7）。实测：不配 securityJsCode 时基础底图 + 图层 + MouseTool/HeatMap 插件均可用；README 已写明 2021-12-02 后申请的 key 需配套安全密钥。仓库内仅保留 `.env.example` 占位符。

### 8.4 已知边界（如实登记）

- AMap MouseTool 框选无法用合成事件自动化验证（高德过滤 isTrusted），该路径经降级模式同代码路径（store.feedbackPolygon → POST /feedback → 重跑 → 增量渲染）端到端实测 + 后端 pytest 覆盖；AMap 侧为官方 API 标准用法（4 行）。
- 中断（HITL）追问流的后端链路由 pytest 覆盖（interrupt → 补充 → 恢复），浏览器端未重复人工验证。
- report 导出、constraint_edit 回传端点为路线图 P3（等任务书），前端不做假按钮。
