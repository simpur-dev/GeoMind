## 2. 设计原则（对齐架构的硬约束）

1. **Query Builder 是唯一 SQL 出口，LLM 永不拼裸 SQL**（§3.2 要点①、§13 风险"LLM 生成 SQL 正确性"）。所有 SQL 由模板化编译产生，参数一律 `%(name)s` 占位符。
2. **空间计算不下放 LLM、不下放前端**：Skill.run 内禁止坐标几何运算；只能下发 SQL 或走高德网关。
3. **空间查询固化两段式**：`lon BETWEEN AND lat BETWEEN`（MBR 预筛，走 `KEY(lon,lat)`）+ `ST_*` 精确复核（压测结论，SPATIAL INDEX 不参与计划）。
4. **SQL 三层卡点**：schema 静态校验 → 小样本 dry-run → EXPLAIN 算子断言，任一失败即拒绝执行并向上层返回原因（§13 风险应对）。
5. **核心冻结边界**（§5.6）：不改 L2 主状态图骨架协议、不改 `SkillRegistry` 注册发现协议、不改已建表 DDL、不改四条铁律。新场景只能加 Skill 包 / migration / 图层 JSON。
6. **单变量验证**：每模块落地即跑对应 pytest + 一条手工验收命令，不留"攒到最后一起测"的代码。

### 3.2 B DB 连接层（`backend/db/connection.py`）

```python
class OBConnection:
    """pymysql 薄封装：连接池（线程安全，默认 4 连接）+ 只读事务 + 服务端计时。"""
    def execute(self, sql: str, params: dict | None = None) -> list[dict]
    def execute_timed(self, sql, params) -> tuple[list[dict], float]   # 服务端 SYSDATE(6) 打点
    def explain(self, sql, params) -> str
```

关键约束：
- DSN 来自 `config.py`；**空密码 + `--ssl-mode=DISABLED`** 固化为连接参数（本机实测口径）。
- 所有查询**参数化**，禁止 `%s` 字符串拼接用户输入。
- 计时一律服务端 `SYSDATE(6)`（本机实测 `NOW(6)` 对短查询会出负值，见《开发进度.md》踩坑记录）。

### 3.3 C Query Builder（L4 唯一 SQL 出口，`backend/query_builder.py`）

**输入**：`HybridQuerySpec`（Pydantic，四类约束）。

```python
class SpatialConstraint(BaseModel):
    center: tuple[float, float] | None      # (lon, lat) WGS84
    radius_m: float | None                  # 米
    polygon_wkt: str | None                 # 等时圈/框选
    time_bucket: str | None

class ScalarConstraint(BaseModel):
    category_id: int | None
    min_rating: float | None
    status: int = 1
    attrs_filter: dict | None               # JSON 属性（-> '$.key' = value）

class SemanticConstraint(BaseModel):
    keywords: list[str] = []                # → ngram 全文谓词（AND 语义 '+kw1 +kw2'）
    query_text: str | None                  # → embedding → cosine ANN
    limit: int = Field(10, le=200)

class HybridQuerySpec(BaseModel):
    spatial: SpatialConstraint
    scalar: ScalarConstraint
    semantic: SemanticConstraint
    target: Literal["dim_poi", "fact_store", "knowledge_doc"] = "dim_poi"
```

**输出**：`CompiledQuery(sql, params, expected_operators, plan)`。

编译规则（固化压测结论）：
1. `radius_m` → 换算为度 `r_deg = radius_m / 111_320`，生成 `lon BETWEEN %(x0)s AND %(x1)s AND lat BETWEEN %(y0)s AND %(y1)s`；`polygon_wkt` → 生成 MBR 包围盒（库内算，用 `ST_X/ST_Y` 不适用，由 Python 侧对 WKT 顶点求 min/max——**这是合法的边界计算，不是空间裁决**）。
2. 精确复核：`_ST_Dwithin(location, ST_GeomFromText(%(center_wkt)s), %(r_deg)s)` 或 `ST_Contains(ST_GeomFromText(%(poly)s), location)`。
3. `keywords` → `MATCH(name) AGAINST (%(match_expr)s IN BOOLEAN MODE)`，**AND 语义**（`'+kw1 +kw2'`）；`query_text` → embedding provider 转向量 → `ORDER BY cosine_distance(emb, %(qvec)s) APPROXIMATE LIMIT %(limit)s`。
4. `attrs_filter` → `attrs->'$.k' = %(v)s`（JSON 用参数化字符串值）。
5. **两段式断言**：只要出现空间谓词，编译产物必须同时含 MBR 条件，否则 `CompileError`。

**三层卡点**：

| 层 | 检查 | 失败动作 |
|---|---|---|
| 静态校验 | 单语句；表/列名 ∈ schema 白名单（启动时从 `information_schema` 拉取缓存）；禁 `SELECT *`；空间谓词必须配对 MBR；向量排序必须带 `APPROXIMATE` 且 `LIMIT ≤ 200`；禁注释外多余分号 | 抛 `SQLValidationError`，带原因码 |
| dry-run | `SELECT ... LIMIT 1` 包装执行，超时 3 s | 抛 `DryRunError` |
| EXPLAIN 卡点 | 按 `target` 与是否有语义条件断言算子：向量目标必须含 `VECTOR INDEX ADAPTIVE SCAN`；空间/标量目标必须含 `TABLE RANGE SCAN` 且索引名 ∈ {`idx_poi_bbox`, `idx_poi_grid`, `idx_poi_cat_stat_rating`} | 抛 `PlanAssertionError`，**并把实际计划随异常返回**（上层可降级到写法 B 两阶段） |

> EXPLAIN 断言不通过时**不是简单失败**：返回 `PlanViolation(expected, actual)`，由 Skill 决定降级策略（这正是架构 §6.6"两种写法选型决策"的工程落地）。

### 3.4 D Embedding Provider（`backend/embeddings/`）

```python
class EmbeddingProvider(ABC):
    dim: int
    @abstractmethod
    def embed(self, text: str) -> list[float]        # 单条
    def embed_batch(self, texts: list[str]) -> list[list[float]]

class SyntheticEmbeddingProvider(EmbeddingProvider):
    """与 backend/etl/seed_cd.py 同一构造规则（类目 + 语义标签两级近邻），
    保证查询向量与库内 2 万合成向量同分布 —— 演示可复现、可解释。"""

class BGEProvider(EmbeddingProvider):
    """真实模型占位：dim=1024，接口与 Synthetic 一致；接入时只改 config 的 provider 名。"""
```

**诚实边界**：`SyntheticEmbeddingProvider` 只用于验证链路与索引行为，**任何对外表述必须注明"合成向量"**（与 `seed_cd.py` 头部声明一致）。真实场景切换 `EMBEDDING_PROVIDER=bge` 即可，SQL 与表结构零改动。

### 3.5 E Skill 层（`backend/skills/`）

严格按架构 §5.2/§5.3 实现，**签名不改**：

| 文件 | 内容 |
|---|---|
| `base.py` | `ToolContext` / `SkillContext` / `SkillMetadata` / `SpatialSkill(ABC, Generic[I,O])`，方法 `build_plan` / `run` / `synthesize` / `render_spec` |
| `registry.py` | `SkillRegistry` 单例 + `@register_skill` + `discover()`（pkgutil 扫描 `backend.skills`） |
| `atomic/multi_modal_search.py` | 入参 = HybridQuerySpec；产出 `PoiCandidate(poi_id, name, dist_m, sem_dist, match_score, rating)`；内部走 QueryBuilder 三层卡点 |
| `atomic/spatial_join_agg.py` | 网格聚合：`grid_id` 冗余列 JOIN（**不用 ST_Contains**）；支持 `center+radius` → 自动推导网格 id 列表 |
| `atomic/traffic_grid_agg.py` | 客流聚合（time_bucket 过滤 + 排序 + limit） |
| `atomic/knowledge_search.py` | `knowledge_doc` 全文 + 向量混合 |
| `atomic/poi_detail.py` | 点查 + 逆地理兜底（高德网关 stub，未配置 key 时降级为返回库内 address） |
| `scenes/site_selection/` | 场景 Skill：`build_plan` 返回 DAG 模板；`run` 编排 `multi_modal_search → spatial_join_agg → score_and_rank`；`synthesize` 产出可解释结论；`render_spec` 产出 Map Spec |

`score_and_rank`（打分）**放在场景 Skill 内的纯 Python 步骤**（架构 §6.6：融合排序不写进单条 ANN SQL，对 SQL 返回的小结果集计算）：
`score = w1*语义 + w2*客流 + w3*评分 - w4*竞品密度`，权重来自 `config.py`，可解释可复现。

**高德网关 stub**（`backend/services/amap_gateway.py`）：接口签名按真实 API（`geocode` / `regeo` / `isochrone` / `path`），未配置 key 时抛 `AmapUnavailable`，调用方按"库内数据兜底"处理——**阶段 0 不产生任何外部调用**。

### 3.6 F MCP Server（`backend/mcp_server/server.py`）

按架构 §5.4 实现，两处工程化增强：
1. **启动即绑定**：`discover()` → 遍历注册表 → `mcp.tool(name, description, annotations=dict(annotations=input_schema))`；`tools/list` 因此动态可见。
2. **SkillContext 注入**：MCP 请求无会话态，用 `session_id` query param 或 `X-GeoMind-Session` header 恢复 Spatial State（缺失则建新会话）。

验收命令：起服务后用 MCP client 调 `tools/list`，断言工具数 ≥5 且每个含 `inputSchema`。

### 3.7 G Spatial State + 状态仓库（`backend/state/`）

**模型**：架构 §4.1 顶层字段完整落成 Pydantic v2：

```python
class StepNode(BaseModel):
    id: str; skill: str; status: Literal["pending","ready","done","stale","failed"]
    depends_on: list[str] = []; result_ref: str | None = None
    derived_from: list[str] = []

class LayerSpec(BaseModel):
    id: str; kind: Literal["points","heatmap","polygon","line"]; data_ref: str
    style: dict = {}; status: str; derived_from: list[str] = []

class SpatialState(BaseModel):
    session_id: str; scene: str; version: int
    slots: dict[str, Any]; steps: list[StepNode]; layers: list[LayerSpec]
    evidence: list[dict] = []; updated_at: datetime
```

**仓库**（`backend/state/repository.py`）：读写 `scene_solution` 表。

```python
class StateRepository:
    def load(self, session_id) -> SpatialState | None
    def save(self, state: SpatialState) -> int          # version 自增，写回 OB
    def mark_stale(self, session_id, node_id) -> list[str]   # 反向依赖闭包标 stale，返回受影响节点
    def replan(self, session_id) -> list[str]                # 拓扑序返回待重算节点
```

局部重算语义：`mark_stale(s1)` → 所有 `derived_from`/`depends_on` 传递可达的节点标 `stale`；`replan()` 按 DAG 拓扑序输出 `stale` 节点。**这是架构 §4.3 依赖图机制的落地，也是"中间状态复用"铁律的工程保证。**

### 3.8 H LangGraph 7 步骨架（`backend/brain/`）

```
intent → constraints → candidates → spatial_join → decide → render → feedback
```

| 节点 | 类型 | 说明 |
|---|---|---|
| `intent` | 规则 + 可插拔 LLM | 规则意图器：槽位（city/category/keywords/radius）正则 + 类目词表；产出 `IntentResult(scene, slots, confidence)`。`confidence < 0.6` → `interrupt({"question": ...})`（HITL，对标 MCP Elicitation） |
| `constraints` | 确定性 | slots → `HybridQuerySpec` |
| `candidates` | 确定性 | 调 `multi_modal_search` |
| `spatial_join` | 确定性 | 调 `spatial_join_agg` |
| `decide` | 确定性 + LLM 摘要 | `score_and_rank` + `synthesize`（FakeLLM 生成可解释结论文本） |
| `render` | 确定性 | `render_spec` → Map Spec JSON |
| `feedback` | 确定性 | 写回 `knowledge_doc`（采纳/否决样本，走 OB） |

**图结构固定为 7 节点**（架构：7 步固化为图结构，可审计、不漂移、省 token）；只有 `intent` 节点可 ReAct/追问，其余节点纯确定性。

**checkpointer**：`MemorySaver`（阶段 0）；`StateRepository` 负责 OB 侧持久化，两者分工 = 图执行态在内存、业务态在 OB（架构 §2.2 L5）。

**LLM 网关**（`backend/llm/gateway.py`）：`LLMGateway(ABC).chat(messages, schema) -> dict`；实现 `FakeLLMGateway`（模板化输出，供测试与演示）；真实 `DoubaoGateway` / `DeepSeekGateway` 留类骨架，按 §8"OpenAI 兼容"接入，**本轮不实例化**。

## 4. 端到端数据流（本轮口径）

```
CLI/HTTP "春熙路附近安静可自习的咖啡馆"
  → intent        规则意图器 → scene=site_selection, slots={category:咖啡茶饮, keywords:[安静,自习], center, radius_m:1500}, conf=0.82
  → constraints   HybridQuerySpec
  → candidates    QueryBuilder 编译（两段式 MBR + ST 复核 + 全文 AND + cosine ANN）
                    → 静态校验 → dry-run → EXPLAIN 断言（VECTOR INDEX ADAPTIVE SCAN / idx_poi_bbox）
                    → OB 执行 → 10 条候选（dist_m, sem_dist）
  → spatial_join  grid_id 冗余列 JOIN → 25 网格客流 × POI 密度
  → decide        score_and_rank + synthesize（FakeLLM）→ 可解释结论
  → render        Map Spec（points + heatmap 两种 kind）
  → feedback      状态 version++ 写回 scene_solution；样本写 knowledge_doc
```

## 9. 实施步骤（每步可独立验证）

| 步 | 内容 | 验证 | 预计耗时 |

## 10. 风险与备选

| 风险 | 概率/影响 | 应对 |
|---|---|---|
| 依赖安装（PyPI 可达性、langgraph 体积） | 中 / 高 | 先探测 pip 源可达性再装；若 langgraph 装不上，备选：先用纯 Python 状态机实现 7 步（接口保持一致），LangGraph 后续替换（架构已留"不用 AutoGen/CrewAI"的结论，但状态机可平滑迁移） |
| pymysql 与 SeekDB 协议细节（向量列返回为 str） | 中 / 中 | 已在压测中确认 MySQL 协议直连可用；向量字面量按 str 处理，不反序列化 |
| EXPLAIN 断言过严导致正常查询被拒 | 中 / 中 | 断言按"算子 ∈ 期望集合"而非精确等值；失败时返回 `PlanViolation` 交上层降级（两阶段写法 B），不静默 |
| LangGraph API 版本差异（interrupt / checkpointer 签名） | 中 / 中 | 安装后先跑一个最小 2 节点冒烟测试再写 7 步；版本记入 README |
| 合成向量与真实 BGE-m3 切换后检索质量变化 | 低 / 中 | Provider 抽象隔离；切换后重跑对拍测试（用真实向量重新灌一批再回归） |
| 范围蔓延到前端/真实 LLM | 中 / 高 | §1.3"不做"清单作为评审基线；新增需求先更新本设计文档再动手 |
