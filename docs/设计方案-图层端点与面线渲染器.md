## 2. 范围

做：l_iso（必做）+ l_route（端点分支与渲染器，不接触发链路）、裸 SQL 两处收口、polygon/isochrone/route 两档渲染器、图层开关中文标签、前端类型门禁修真、等时圈进图状态。

不做：`path_planning` 接图与场景编排（卡 5）、意图器的 `iso_minutes/travel_mode` 槽位（卡 5）、LLM 意图器（卡 4）、chips 点改时间预算（卡 6）、trajectory/grid/marker 三种 kind。

## 3. 设计决定

**D1 端点形状与坐标系（§9.6）**：`l_iso` **透传** reachability 的内联 GeoJSON（路由层出口已是 GCJ-02 闭合环，端点不再二次转换）；`l_route` 的 `polyline` 是 WGS84（路由层主字段口径），出口前逐点 `wgs84_to_gcj02`。两者都返回 FeatureCollection，与 l_candidates/l_heat 同构。**图状态无产出 → 空 FeatureCollection，不 404**；404 只保留给未知 layer id。

**D2 端点取数写成模块级纯函数**：`iso_feature_collection(state_iso)` / `route_feature_collection(state_route)` 放 `routes.py` 模块级，不闭包 services——纯函数才能不打 HTTP、不连库直接单测，也才能测「脏数据不 500」这类边界（形状不合法一律降级成空集）。

**D3 裸 SQL 收口用「常量映射」而不是「传列名」**：`compile_point_query(PointQuerySpec(table, ids, time_bucket))`，列名来自 `_POINT_COLUMNS`（`dim_poi→(poi_id,lon,lat)`、`fact_traffic_grid→(grid_id,center_lon,center_lat)`），调用方传不进任何标识符；主键逐个 `%(id0)s` 参数化，`ids` 上限 200 与 `validate()` 的 `max_limit` 天花板对齐。**不别名 `center_lon AS lon`**：`_extract_columns` 会按表白名单校验 SQL 里出现的已知列名，别名会把 `lon/lat` 扯进网格表 → 直接触发跨表串列拦截（这条是实跑撞出来的，注释写在方法里）。三层卡点由新增的 `execute_checked()` 串起来（validate→dry_run→assert_plan→执行），让 L1 端点复用与 Skill 完全相同的卡点，不另写一套。

**D4 等时圈进图 = 节点体扩展（§5.6 冻结边界的具体解释）**：`GRAPH_NODES`、条件边、`build_graph` 结构一行不动；只在 `spatial_join` 节点体里追加一次 `ctx.tools["reachability"].run(...)`，`BrainState` 增一个 `isochrone` 键。理由：§2.3 把第 4 步「空间计算」定义为 L4 路由的职责，节点体本就是它的落点；冻结的是**主状态图骨架**，不是「节点永远不许多调一个工具」。新增断言把骨架钉死：`set(nodes) - {__start__,__end__} == set(GRAPH_NODES)`。失败不抛异常，落空产出 `{}`，图不中断。

**D5 图层声明单一来源**：`site_selection.render_spec` 不重造 isochrone 图层，直接把 `state["isochrone"]["render_spec"]` 反序列化后挂进 layers（断言逐字段相等）。href/data_ref/style 一旦两处定义必然漂移，这是 §9.3 契约层的老坑。

**D6 时间约束只落「接收端」**：`spec` 新增 `iso_minutes` / `travel_mode` 两键，节点有则用、无则沿用 Skill Schema 默认（driving/15min），**图里不另写一份默认值**。与 `time_bucket`（客流时段）严格分字段——两者语义不同，混用一个字段会让「15 分钟可达」和「工作日晚间」互相覆盖。意图器填这两个槽位属卡 5（用户裁定）。

**D7 测试态强制无高德 key**：等时圈进图后，`TestClient(create_app())` 的一轮 chat 会经路由层调真实 API。conftest 在 import 前把 `GEOMIND_AMAP_KEY` 置空（与既有 `GEOMIND_LLM_PROVIDER=fake` 同一手法），测试态一律走正圆降级、零外部请求；需要在线形态的用例自己注入 `MockTransport`。**这条是接图的必要条件，不是可选优化。**

**D8 镜头必须分两种口径**（实测撞出来的真缺陷）：`viewport_from_center` 是为候选簇调的经验档位（1.5 km 只给 z15，视野约 1.1 km，靠中心的簇点看不全外圈也不影响判读）；等时圈是公里级几何，得按「装得下」算。新增 `viewport_covering(center, radius_m, margin=1.2)`：按降级画布公开 documented 的投影模型 `span(z)=0.02°/2^(z-13)` 反解 zoom，使 `span ≥ 2R·margin`。两函数并存，POI 镜头的两条钉死断言（1500→z15、3200→z14）不变。

**D9 前端只消费不决定**：几何类型契约 `types.ts` 从只支持 Point 拓宽为 `Point | LineString | Polygon` 并加 `isPoint()` 守卫；样式（含 `dash`）全部来自 `spec.style`——为此把 `dash/width` 补进后端 `_ISO_STYLE`，而不是前端写死；未知 kind 仍走 `console.warn` 跳过（既有行为，registry 接口不动）。

## 5. 实施顺序

1. 先修真前端门禁（否则后续「0 错」是假绿）→ 清掉暴露出的 4 类既有错误。
2. `compile_point_query` + `execute_checked` → 实 SeekDB 验三层卡点与 EXPLAIN 算子。
3. `routes.py` 收口 + l_iso/l_route 分支与纯函数 → 既有 l_candidates/l_heat 用例回归。
4. 等时圈进图（graph 节点体 + conftest 无 key + 场景转发）→ `test_graph` 断 degraded 产出与骨架仍 7 节点。
5. 前端几何契约 + 两档三渲染器 + 标签 + store 映射。
6. 镜头装箱（`viewport_covering` + 场景选择）——浏览器实测发现等时圈溢出画布后补的一步。
7. 全量质量门 → 浏览器两档实测 → 变异检查 → 文档与 commit。

## 7. 风险与遗留

| 项 | 说明 |
|---|---|
| 截图证据 | 功能证据齐（DOM/网络/构造计数/控制台无警告），像素截图需内嵌 Browser 面板打开后补 |

### 8.2 本轮实测修掉的两个坑（都不是设计阶段想到的）

1. **前端类型门禁是空转的**。`npx vue-tsc --noEmit` 在 solution 形态的根 `tsconfig.json`（`"files": []` + references）下列出 **0 个文件**，`typecheck`/`build` 一直在绿一个不存在的东西。改成 `-p tsconfig.app.json` 后纳入 **17 个文件**，立刻暴露 4 类既有错误：`ChatPanel.vue:62` 模板里的 `{ question?: string }` 断言把 vue-tsc 解析器打崩（4 条）、`amap.ts:136` 用了 `Map` 接口未声明的 `add`、`session.ts` 的 `lastQuery` 根本没进 `SessionState`（框选重跑用的 query 文本首帧是 undefined）、`registry.ts` 的 `renderMapSpec` 全仓无调用方（死代码，顺带 `prev` 未使用）。**卡片验收项「vue-tsc 0 错」在修门禁前是无意义的**，故纳入本卡范围。
2. **等时圈渲出来了但在画面外**。降级画布实测 `<path>` 的 `d` 投影坐标到 `y=-1855`、bbox 8682×4023 px，而画布只有 800×600——`viewport_from_center` 的经验档位是给候选簇调的（1.5 km 只给 z15），装不下公里级圆。新增 D8 的 `viewport_covering` 反解 zoom 后复测：13 个投影点落在 x∈[129,671]、y∈[165,435]，圆整体在画布内。这条是「渲染器正确」与「用户看得见」之间的差距，只看 DOM 有没有 path 会漏掉。
