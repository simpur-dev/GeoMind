### 生产库落地新增的硬结论（已写入架构文档 v1.4）

| 结论 | 证据 | 影响 |
|---|---|---|
| **全文 MATCH 谓词能进入 `ADAPTIVE SCAN (PRE-FILTER)`** | EXPLAIN filter 列表含 `[MATCH(name) AGAINST(...)]` 且标注 `pushdown_match_filter`；知识库表同样成立 | 架构文档 §6.6「全文能否进预过滤【待实测】」关闭；四模可一趟索引扫描完成过滤 |
| **加 MBR 后优化器自动切换驱动索引** | 含 MBR：`idx_poi_bbox`，EST.TIME 17324 μs；去 MBR：`idx_poi_cat_stat_rating`，EST.TIME 86339 μs | 优化器预估代价差 5 倍，MBR 预筛在最优路径上是被认可的 |
| **多模过滤真的在索引扫描阶段生效（可证伪对照）** | 纯向量 ANN top10 距离 582–18731 m，仅 1 条在 1.5 km 内；四模 top10 全部在圈内且全为「XX自习咖啡」 | 排除「召回后再过滤」的退化路径 |
| 五模（+JSON 属性）可用 | `attrs->'$.parking' = true AND attrs->'$.wifi' = true` 返回 3 条 | 单表的五模形态完整成立 |
| 空间连接两种写法结果逐行一致 | `ST_Contains` JOIN 与 `grid_id` JOIN 的 25 网格计数完全相同 | 冗余列方案可安全替代，无精度损失 |
| 网格边界舍入会导致 grid_id 错位 | 首轮 20000 行中有 1 行不匹配 | ETL 必须用 `round(lon,6)` 后的坐标算 grid_id |

### 本次复测新增的硬结论（已写入架构文档 v1.4 与实测报告）

| 结论 | 影响 |
|---|---|
| SRID 4326 列级声明报 3548、**注册语句报 1064（不支持）** | 两条路堵死 → DDL 固化 SRID 0，原「待实测」待办关闭 |
| 空间连接 `ST_Contains` JOIN + GROUP BY **功能正确但 EXPLAIN = NESTED-LOOP + 双侧全扫** | 聚合可下推但无索引加速；10 万级若仍全扫，改「`_ST_Dwithin` 预筛 + 应用层归属」或「冗余网格 ID 列 + 普通索引 JOIN」 |
| 新增可用：`ST_Contains`/`ST_Within`/`ST_Centroid`/`ST_Area`/`ST_Distance`（度） | 可下推白名单由 4 个扩到 9 个 |
| `ST_Union_Agg`/`ST_Intersection` 确认不存在 | 交并运算只能走应用层 Shapely 或高德 |
